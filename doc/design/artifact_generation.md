# Artifact Generation

This document describes the *artifact generation* system.
This system is responsible for generating meaningful artifacts
and the history and lore fragments that accompany them.

## Generation Process

Each artifact is generated for a specific origin culture.
Artifact data is generated by following an iterative process.

### Artifact Seeding

Before generating a concrete history, an artifact "seed" is created which is used
as an input to the history generation.

This seed is generated in two phases:

1. The semantic seed is generated based on the properties of the origin culture.
   This seed describes the type, creation trigger, and purpose of the artifact.
2. Using the semantic seed, a contextual seed is generated describing
   the social context in which the artifact is intended to be used.

### Physical Properties

Once the artifact seeds have been generated, the physical properties of the artifact
are generated based on the material culture mappings of the origin culture.

First, the origin culture's combination rules are used to resolve different
semantic concepts to produce an initial set of physical properties.

Any remaining undefined properties are then populated based on the semantic and syntactic mappings.

### Creation Event

The first event is the creation of the artifact.

A creator is identified from the plausible historical figures of the origin culture,
or generated based on the origin culture's properties.

A trigger event may be optionally identified from the origin culture's history.

Based on these aspects, a concrete event is created describing:

* The point in time when the artifact was created
* The reason why the artifact was created (trigger event or otherwise)
* The artifact's intended purpose
* The location where the artifact was created

### Other Events

Once the creation event has been generated, a number of other events are generated.
The number is random but will be higher the more significant the artifact.
The exact ranges will need to be determined through experimentation.

For each event:

* The event time is generated by adding a random number to the time of the previous event in this chain
* Optionally: another recent event may be used as a trigger
* The nature of the event is generated (e.g. used in a ritual, traded, stolen)
* A location is identified for the event by querying the world database
* Event participants are retrieved or generated based on the nature of the event

The final event in this chain indicates the final resting place of the artifact.
The only difference in this event is that the location is pre-determined,
since the final location of the artifact is determined when it is generated.

### Lore Fragments

For each event in an artifact's history, lore fragments may be generated.
Whether or not a fragment is generated is governed by the following rules:

* Creation and final events always result in a lore fragment
* For other events, there is a chance to create a lore fragment
  (the exact probability will be determined through experimentation)

This ensures that players will always be able to find out where an artifact was created
and where it is now located in the world.

For each lore fragment:

* The nature of the lore fragment is determined - whether it is a primary or secondary source
* The author of the lore fragment is determined:
  * For primary sources, the author is one of the event participants
  * For secondary sources, the author is a scholar who might plausibly discover and write about that event
    * This person may be retrieved from the existing world or generated
* The time of authorship is selected from the range of the author's lifetime
* Based on the author, the nature of the lore fragment, the event being described,
  and the time of authorship, the author's relationship to the event is determined
* Based on the author, the fragment language is determined

Once these properties are known, the concrete text of the lore fragment is generated.

A given lore fragment may describe some or all of the following:

* The event itself
* Historical context of the event
* Motivations of the event participants
* Physical properties of the artifact
* Cultural context of the artifact
* Current location of the artifact

Transformation rules may be applied to these descriptions to generate
historically authentic inaccuracies.

The transformation rules may be either:

* Explicitly authored, with hand-crafted trigger conditions and outcomes
* Implicitly derived from the origin and author culture semantic mappings

Based on the number of transformation rules applied,
a reliability score is assigned to the lore fragment.
This is determined as a percentage of the lore fragment's information categories
that were *not* transformed.

#### Explicit Rules

Each explicit transformation rule has a trigger condition based on the properties
of the event and the author.
When more than one rule applies, the applied rule is selected at random.

The transformation rule itself describes how that original property of the lore fragment
is altered to match how the author would describe it.

It will be necessary to tune transformation rules through experimentation.

#### Implicit Rules

When no explicit rule is applicable, the system may fall back to a procedural misunderstanding
based on the semantic mappings of the origin and author cultures.

For example, if the origin culture has the semantic mapping `grief -> sapphire`,
and the author culture has the mapping `calm -> sapphire`,
`calm` may be substituted for `grief` in the lore fragment.

Bayesian inference, based on the weights in the semantic mappings, is used to determine the rate
at which each concept is assigned to a material encountered by an author. 

## World Database

The world database stores information about the world that is used
in the generation process.

It also provides an interface to query the stored objects based on properties
(e.g. "get all locations associated with culture X with Y purpose").

### Time

The world database represents time as a single linear sequence.
For the purpose of world history, the most granular measurement of time is the year.

### Cultures

Cultures are explicitly authored rather than being procedurally generated.

The world database stores the following properties for each culture:

* Name
* Naming conventions
* Values
* Religion
* Languages (language ref -> relationship)
* Material culture
* Active time period (range of years)
* Relationships to other cultures (culture ref -> relationship)

#### Material Culture

Material culture mappings describe how a culture's seed properties
are translated into concrete physical properties during artifact generation.

These mappings are explicitly authored.

There are three kinds of mappings:

* **Semantic mappings** connect emotional, social, and functional concepts to possible materials/forms.
  Each mapping has the following properties:
  * Concept - the semantic concept that this mapping starts with
  * Weighted lists of physical properties corresponding to the concept:
    * Materials
    * Colours
    * Decorations
* **Syntactic mappings** connect artifact types and usage contexts to possible forms.
  Each mapping has the following properties:
  * Filter - the artifact type and usage context this mapping applies to
  * Weighted lists of physical properties corresponding to the filter:
    * Scales
    * Forms
    * Construction techniques
* **Combination rules** describe how conflicting semantic mappings are resolved.
  Each rule has the following properties:
  * Concept filter - the constraint describing the two semantic concepts
  * Resolution - one of:
    * Dominance: one concept takes precedence over the other
    * Synthesis: a specific physical property satisfies both concepts simultaneously
    * Layering: different physical properties express different dimensions

### Locations

Locations are explicitly authored rather than being procedurally generated.

The world database stores the following properties for each location:

* Names (culture ref -> name)
* Kind (settlement, temple, etc.)

### People

The most significant people in the world's history are explicitly authored,
however new people may be generated as required when determining the history of an artifact.

The world database stores the following properties for each person:

* Name
* Culture
* Values
* Social role
* Languages spoken (language refs)
* Lifespan (range of years)

When a person is required for history generation, an existing person may be retrieved
from the world database, or a new person generated.
Whether or not a new person is generated is dependent on how many people exist
who already satisfy the constraints of a given query.

The exact generation rate will need to be determined based on experimentation.

### Events

The most significant events in the world's history are explicitly authored,
however new events are generated as part of artifact generation.

The world database stores the following properties for each event:

* Timestamp (year in which the event occurred)
* Trigger (event ref)
* Kind (ritual, trade, theft, etc.)
* Location (location ref)
* Participants (person ref -> role)
* Optional: Artifact (artifact ref)

### Artifacts

Some more significant artifacts are explicitly authored,
while minor artifacts are generated.

The world database stores the following properties for each artifact:

* Semantic seed:
  * Type
  * Creation trigger
  * Purpose
* Contextual seed:
  * Intended user
  * Intended usage context
* Physical properties:
  * Material
  * Colour
  * Decoration
  * Scale
  * Form
  * Construction technique
* Creator (person ref)
* Referenced figures (person refs)
* Current location

### Languages

The languages of the world are explicitly authored.

The world database stores the following properties for each language:

* Name
* Contemporary status (alive/dead)
* Parent (language ref)

### Transformation Rules

Transformation rules describe how the content of lore fragments
is generated based on rules about the people and cultures involved.

These rules are explicitly authored.

The world database stores the following properties for each transformation rule:

* Relevant information category (lore fragment information category ref)
* Trigger condition - a structured constraint that allows filtering for applicable transformations based on:
  * Cultural dimension
  * Nature of the difference between the two cultures
  * Author's cultural position
* Replacement text (generation grammar)
* Reasoning (for diagnostic purposes)

### Lore Fragments

Lore fragments are generated as part of artifact generation.

The world database stores the following properties for each lore fragment:

* Authoring time
* Artifact (artifact ref)
* Event (event ref)
* Cultural origin (culture ref)
* Author (person ref)
* Author perspective: participant, contemporary outsider, successor, distant
* Language (language ref)
* Source type (primary or secondary)
* Author-event relationship
* Information categories
* Reliability score (percentage of untransformed information categories)
* Generated text
